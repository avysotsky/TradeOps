## Purpose

Extend the validated non-mutating path by one execution-adjacent step:

```text
ResearchDecision
→ RebalancePlan
→ RebalanceOrderIntent
→ deterministic TradingSignal
→ existing RiskEngine.CheckAsync
→ risk approved
→ deterministic execution dry-run envelope
→ auditable runtime result
```

This slice must prove that a risk-approved rebalance intent can be translated into the same stable execution identity shape used by TradeOps without creating, submitting, persisting, cancelling or reconciling a real order.

No broker mutation is allowed.

## Existing production semantics to reuse

Reuse unchanged where appropriate:

```text

TradingSignal

OrderSide
OrderType.Market
```

The existing production `OrderManager` and `SignalExecutionService` are reference semantics only for this slice.

Do not call them.

## Why OrderManager is not used

Current `OrderManager.ExecuteSignalAsync` couples:

1. client-order-id generation;
2. existing-order lookup;
3. risk check;
4. local order persistence;
5. order-state transition to Submitted;
6. alerts;
7. `IExchangeClient.PlaceOrderAsync`;
8. timeout reconciliation.

VS-17 must stop before steps 4–8.

Therefore VS-17 must not attempt to make `OrderManager` "partially dry-run".

## Dry-run execution envelope

After VS-16 produces an allowed risk preview, construct a tool-local immutable result with semantics equivalent to a pre-submit execution instruction.

Recommended shape:

```json
{
  "executionDryRun": {
    "mode": "dryRun",
    "state": "Prepared",
    "signalId": "...",
    "decisionId": "...",
    "clientOrderId": "trd-...",
    "symbol": "SAMP",
    "side": "Buy",
    "orderType": "Market",
    "quantity": 30.00,
    "referencePrice": 100.00,
    "estimatedNotional": 3000.00,
    "riskAllowed": true,
    "mutationPerformed": false,
    "brokerRequestSent": false,
    "persistencePerformed": false
  }
}
```

Exact field names may be adjusted if justified, but the semantics must stay explicit and auditable.

### Required invariants

For an allowed risk result:

- `signalId` is exactly the deterministic VS-16 signal ID;
- `clientOrderId` is generated by the existing production `ClientOrderIdGenerator`;
- symbol, side and quantity equal the integrated `RebalanceOrderIntent`;
- `orderType = Market`, matching current `OrderManager` placement semantics;
- `riskAllowed = true`;
- `mutationPerformed = false`;
- `brokerRequestSent = false`;
- `persistencePerformed = false`.

For a rejected risk result:

- dry-run execution must not become `Prepared`;
- recommended state: `BlockedByRisk`;
- no broker request;
- no persistence;
- no Order entity;
- no Submitted state;
- no exchange call.
